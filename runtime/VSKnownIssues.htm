Microsoft Visual Studio 2005 已知问题

本文列出了使用 Microsoft Visual Studio 2005 时可能遇到的问题。有关与安装产品相关的问题，请参考 readme.htm。

有关最新的已知问题，请参见联机 Visual Studio 2005 已知问题，网址为：http://go.microsoft.com/fwlink/?LinkId=51326

1. Visual Studio

1.1   VC++ Visual Studio 2005 测试版 2 项目文件无法打开 

如果某台计算机上的 Visual Studio 安装位置与当前计算机上的安装位置不同，则使用当前计算机上的 Visual Studio 2005 最终版本打开上次在该计算机上加载的测试版 2 C++ 项目时，可能会收到错误；如果项目路径已更改，也有可能会收到错误。

解决此问题的方法

编辑项目设置文件。右击解决方案资源管理器中灰显的项目节点并选择“编辑 <项目名>.vcproj”，此操作将在 XML 编辑器中打开该文件。将 InheritedPropertySheets 标记的值更改为“$(VCInstallDir)VCProjectDefaults\UpgradeFromVC70.vsprops”，然后重新加载项目。

 

1.2   在 Windows 2000 中，使用“用应用程序验证工具启动”将生成以下消息：“在 machine_name 上运行的操作系统不支持应用程序验证工具。请升级到 Windows XP 或更高版本。” 

Windows 2000 不支持应用程序验证工具。

解决此问题的方法

升级到 Windows XP 或更高版本。

 

1.3   “用应用程序验证工具启动”将出现以下对话框导致：“未在计算机 machine_name 上检测到应用程序验证工具所需的更新后的系统文件。是否访问 Windows 下载中心以获取更新文件?” 

Visual Studio 安装程序不安装应用程序验证工具所需的系统文件。如果计算机操作系统中没有所需版本的文件，则必须更新该文件，才能使用应用程序验证工具。

解决此问题的方法

在对话框中选择“是”以打开 Internet 浏览器并显示 Microsoft 下载中心站点中的更新链接。安装所需的更新文件。也可以使用以下链接访问 Microsoft 下载中心：
http://www.microsoft.com/downloads/results.aspx?displaylang=zh-cn&freeText=889016

 

1.4   在重置分布式系统设计器中的工具箱之前，工具箱不反映本地 Windows 语言设置

在“选项”对话框中，用户可以将 Visual Studio 设置为使用本地 Windows 语言。但是，在重置之前，分布式系统设计器中的工具箱并不反映该设置。

解决此问题的方法

1) 关闭所有分布式系统设计器（应用程序设计器、系统设计器、逻辑数据中心设计器和部署设计器）。
2) 在工具箱内右击，然后单击“重置工具箱”。
3) 重新打开您要使用的分布式系统设计器。

 

1.5   Windows 98 和 Windows Me 上的远程调试 

问题 1：


如果使用 Visual Studio 2005 通过默认传输对属于某个域（该域具有基于 Windows Server 2003 的域控制器）的 Windows 98 或 Windows ME 计算机进行远程调试，用户在启动 Windows 98/ME 计算机之后大约 10 分钟时，可能会收到以下错误信息：

-------------------------
Microsoft Visual Studio
-------------------------
无法连接到名为“<计算机名>”的 Microsoft Visual Studio 远程调试监视器。访问被拒绝。

原因：基于 Windows Server 2003 的域控制器上必须具有服务器消息块 (SMB) 签名并必须启用它。

问题 2：


如果在 Windows XP 或更高版本的计算机上使用 Visual Studio 2005 对 Windows 98 或 Windows ME 计算机进行远程调试，用户可能会收到以下错误信息。

-------------------------
Microsoft Visual Studio
-------------------------
无法连接到名为“<qualifier_name>”的 Microsoft Visual Studio 远程调试监视器。远程计算机上的“Microsoft Visual Studio 远程调试监视器”无法连接到本地计算机。未能启动 DCOM 通信。请参见“帮助”以协助解决问题。

原因：运行 Visual Studio 2005 的计算机上禁用了“在 DCOM 中匿名登录以进行远程访问”。

解决此问题的方法

问题 1：


1) 将域控制器策略设置为启用 SMB 签名但不需要该签名。
有关如何执行此操作的信息，请访问 http://support.microsoft.com/?kbid= 887429
2) 重新启动域控制器。
3) 重新启动安装了 Visual Studio 2005 的计算机。
4) 重新启动运行 Windows 98/ME 的计算机。

问题 2：


要在运行 Visual Studio 2005 的计算机上允许“在 DCOM 中匿名登录以进行远程访问”，请按照以下说明操作：
1) 在命令提示符下，键入 dcomcnfg，然后按 Enter。此时将打开“组件服务”。
2) 在“组件服务”中，展开“组件服务”，展开“计算机”，然后展开“我的电脑”。
3) 在工具栏上，单击“配置‘我的电脑’”按钮。将打开“我的电脑”对话框。
4) 在“我的电脑”对话框中，单击“COM 安全”选项卡。
5) 在“访问权限”下，单击“编辑限制”。将打开“访问权限”对话框。
6) 在“组”或“用户名”下，单击“匿名登录”。
7) 在“匿名登录的权限”下，选中“远程访问”复选框，然后单击“确定”。
8) 重新启动计算机。

1.13   对 ASP.NET 应用程序运行代码覆盖率可能使 web.config 处于被更改状态 

对 ASP.NET 项目运行单元测试时，测试引擎需要修改 web.config 文件。有时候这些文件未被清除，并会在随后的测试运行和应用程序运行中产生异常。

解决此问题的方法

从测试运行期间创建的备份中还原原始 web.config 文件。

 

1.14   Windows 98 上限制了对 ReportViewer 控件的支持 

在运行于 Windows98 上的应用程序中使用时，Windows Forms ReportViewer 控件只能得到有限的支持。使用此控件，您只能查看以前在 SQL Server 2005 Reporting Services 报表服务器上发布的报表。不能使用该控件在本地处理模式下查看客户端报表定义 (.rdlc) 文件。

 

1.15   如果 IIS 辅助进程以 SYSTEM 身份运行，则 ASP.NET 的代码覆盖率将无法工作 

如果 IIS 辅助进程以 SYSTEM 身份运行，则无法收集 ASP.NET 的代码覆盖率数据。在 MSDN 中查看系统上 IIS 辅助进程的名称，因为该名称因 IIS 版本而异。您可以使用任务管理器来确定运行辅助进程的用户身份。
注意：如果禁用了代码覆盖率，单元测试将能够正确运行。

解决此问题的方法

将 IIS 辅助进程更改为不以 SYSTEM 身份运行。

1.18   跟踪分析共享 dll 将导致分析使用该 dll 的所有进程 

如果要跟踪分析某个共享 dll，最终可能会分析使用该 dll 的所有进程。

解决此问题的方法

1) 对于不想分析的每个进程，使用 vsperfcmd -proccessoff:PID 关闭分析。
2) 设置 HKCU/software/microsoft/visual studio/8.0/VSPERF/Monitor/Settings/ProcessProfile=Off，启动您的目标进程，然后使用 vsperfcmd -processon:PID 对您要分析的所有进程启用分析。
注意：分析完成后，必须关闭使用该共享 dll 的所有进程，以便关闭监视器并将数据刷新到报表文件。

 

1.19   如何跟踪分析本机生成的（由 ngen 生成的）图像 

尝试检测 ngen 生成的图像将报告一个不正确的 VSP1014 错误。
CLR 将不会加载由 ngen 生成的已检测托管二进制文件。

解决此问题的方法

检测了托管二进制文件本身而不是由 ngen 生成的图像后，必须执行下列操作之一：

1) 删除 ngen 生成的图像，以便 CLR 使用已检测的二进制文件。
-或-
2) 使用 ngen.exe 重新生成二进制文件。

 

1.20   如果使用了 MarkProfile 分析 API 而探查器监视器未运行，将发生崩溃

使用 vsperf.h 提供的 MarkProfile、CommentMarkProfile 或 CommentMarkAtProfile 时，如果探查器监视器未运行，将发生应用程序崩溃。如果您添加 API 调用然后在调试器（而不是探查器）下启动这些调用，则这种情况最为显著。

解决此问题的方法

使用“vsperfcmd -start:sample -output:foo.vsp”启动探查器监视器

如果以下所有情况存在，则类关系图无法显示引用程序集中的类型：
1. 类关系图驻留在 Web 项目中。
2. 引用的程序集安装在全局程序集缓存 (GAC) 下。
3. 引用程序集未安装在 Framework 根目录（“Microsoft.Net\Framework\<版本>\”）下。

解决此问题的方法

从非 Web 项目使引用类型可视化。

 

1.22   已检测的托管 dll 无法在网站项目中加载 

寄宿在网站中的已检测托管用户控件将无法使用 .NET 的默认安全设置进行加载。

解决此问题的方法

探查器驱动程序在第一次使用时，需要自己初始化。如果此初始化行为通过远程桌面会话在 Windows 2000 Server 上发生，将不会为当前会话初始化该驱动程序，而是为以后的会话初始化该驱动程序。 如果尝试在当前会话上启动监视器，将收到 VSP1398 错误，并且监视器将无法启动。

1) 重新启动计算机。
-或-

如果用户被添加到“控制器用户”组但未添加到“控制器管理员”组，则重新启动控制器服务之前，更改将不会生效。用户因而无法连接到控制器。

1.26   在编辑器中重新加载文件时，可能不显示编码更改 

重新加载文件时 Visual Studio 2005 不检测编码中的更改。如果您在当前编辑器的外部更改了文件的编码，或者所执行的源代码管理操作更改了编辑器中打开文件的编码，Visual Studio 将自动重新加载文件。文件的内容在编辑器中重新加载之后可能无法正确显示。

解决此问题的方法


  1. 在不保存更改的情况下关闭文件。
  2. 在“文件”菜单上，选择“打开”，然后选择“文件”。
  3. 在“打开文件”对话框中，单击“打开”按钮旁边的箭头并单击“打开方式”。
  4. 从“打开方式”对话框的列表中，选择用来打开文件的编辑器（如二进制编辑器或资源编辑器）。要用特定的编码打开文件，请选择带编码支持的编辑器，例如“带编码的 XML 编辑器”。
  5. 单击“确定”。
  6. 从“编码”对话框中的“编码”下拉列表中选择正确的编码。
  7. 单击“确定”。

1.29   从 Visual Studio 2003 导入的安装项目和部署项目在生成时无法进行签名 

在 Visual Studio 2005 中生成从 Visual Studio 2003 导入的已启用签名的安装项目和部署项目时，无法对它们进行签名。生成时将在“错误列表”窗口中显示以下消息：“未对文件‘<文件名>’进行签名。部署项目包含已否决的签名属性。有关更多信息，请参见帮助。”

解决此问题的方法

要启用签名，可以在安装项目和部署项目的生成后步骤中，对生成输出调用软件开发工具包工具 Signtool。有关如何执行此操作的更多信息，请查看与上述生成消息相关的帮助主题。您可以通过突出显示“错误列表”窗口中的相应消息然后按 F1 来访问帮助。


要删除已否决的签名项目属性，请执行下列操作：
1. 双击“错误列表”窗口中的相应消息。
2. 在随后显示的对话框中，单击“是”。这将从您的项目文件中删除已否决的签名项目属性。

1.33   如果在 Sleep 上停止，无法通过远程调试调用对象的方法 

如果在远程计算机上运行以下代码，然后通过远程调试连接到运行的代码，并在代码执行到 Sleep() 调用内时中断，则将无法计算变量 c 的成员。

c = New c1     '假定 c1 是有效类
While True
Threading.Thread.Sleep(1000)
End While

解决此问题的方法

跳出 Sleep()，然后将能够正常计算对象。

 

1.34   Visual Studio 2005 Team Edition for Testers：负载测试错误表包含：“未能找到应用阈值规则所需的从属计数器” 

负载测试结果查看器的错误表包含一个错误，其消息为“未能找到应用阈值规则所需的从属计数器”。负载测试包含一个阈值规则，该规则将一个性能计数器与另一个性能计数器进行比较。如果比较性能计数器在采样间隔内未生成实例，将生成此错误。

解决此问题的方法

更改相关的阈值规则，根据某个常量而不是另一个性能计数器进行比较。除了使负载测试无法运行指定的阈值规则外，此更改不会影响负载测试的结果，可以安全地忽略。

执行下列步骤来更改计数器：
1. 编辑负载测试并选择计数器集/负载测试/计数器类别/LoadTest:Request/计数器/Avg.Connection Wait Time/阈值规则。
2. 删除“比较计数器规则”。
3. 右击以添加一条“比较常量”规则。

解决此问题的方法

对于安全环境，开发人员应使用其他序列化机制，二进制序列化或字符串序列化。对于在应用程序间意外共享临时类文件的可能性不大的应用，可以给辅助进程或应用程序模拟标识授予 %windir%\temp 目录的“列出文件夹/读取数据”权限。

    socket.AsyncSelect(FD_READ | FD_WRITE | FD_OOB | FD_ACCEPT | FD_CLOSE);

2. 如果需要服务器套接字屏蔽其他事件，则请使用服务器套接字适用的特定事件列表，例如，如果服务器套接字不希望接收读取操作事件，则还应在调用 AsynchSelect 方法时从事件列表中移除 FD_READ，如 


    socket.AsyncSelect(FD_WRITE | FD_OOB | FD_ACCEPT | FD_CLOSE);

以屏蔽 FD_CONNECT 和 FD_READ 事件。

请参考
http://msdn.microsoft.com/library/default.asp?url=/library/en-us/vclib/html/_mfc_casyncsocket.3a3a.asyncselect.asp 获取 ASyncSelect 方法行为的完整说明。

6.9   Word 模板可以在“普通”视图中打开，但不能在“打印布局”视图中打开，因此非内联控件不会显示 

Word 中不与文本内联的对象仅在“打印布局”视图中可见。默认情况下，添加至 Visual Studio Tools for Office 文档的 UI 控件与文本内联。右击相应控件，依次单击“设置控件格式…”和“布局”，便可以更改布局类型。

默认情况下，Visual Studio Tools for Office 在“普通”视图中打开 Word 模板，因此非内联控件不会显示。

解决此问题的方法

从“普通”视图切换至“打印布局”视图即可显示控件。

 

6.10   在设计时从非活动 Excel 表删除控件可能导致自动生成的代码无法保持最新 

每个工作表都有自己的设计图面，可以根据需要加载。更改工作表（例如，添加、删除或更改控件）时，设计图面将检测这些更改并更新生成的代码。
如果在设计时从非活动表删除控件，则只能部分更新生成的代码，因为尚未实例化设计图面。至少有两种情形会导致出现此问题。第一种情形，利用“管理命名范围”对话框从非活动表删除 NamedRange 控件。第一种情形，在 Visual Studio 的外部打开 Excel 文档，接着移除控件，然后在 Visual Studio 中重新打开文档。

解决此问题的方法

激活工作表，然后使用“管理命名范围”对话框删除 NamedRange 控件。
若要修复生成错误，可以编辑属性、向图面添加控件或从图面删除控件，从而更新每个受影响的工作表。然后，重新生成项目。

 

6.11   Visual Studio Tools for Office 不对 64 位应用程序提供固有支持 

默认情况下，Visual Studio Tools for Office 和其他项目类型生成为“任意 CPU”类型。但是，Visual Studio Tools for Office 解决方案只能在 32 位环境下使用。

解决此问题的方法

要在 64 位计算机上运行 Visual Studio Tools for Office 解决方案，必须在项目属性中将平台目标从“任意 CPU”更改为“x86”，即使要在 64 位 Windows 操作系统中部署应用程序也是如此。此外，还必须对使用 ServerDocument 类的其他类型的应用程序（例如，控制台应用程序或 Windows 窗体应用程序）进行此项更改。
