1. 简介

Microsoft Visual Studio 2005 提供了以下两种便于部署到现场客户端的方法：

  • 管理员安装模式
    使用此方法，用户可以通过 Microsoft Systems Management Server (SMS) 或其他软件分发工具进行部署。最初由网络管理员运行安装程序以选择要部署的功能。系统根据管理员的选择创建一个 .ini 文件，然后，通过在无人参与模式下运行安装程序并指向生成的 .ini 文件来进行部署。在无人参与模式下运行时，安装程序将安装指定的选项，而不进行提示。如果发生错误，安装程序将因失败而自行退出。

    有关使用 SMS 部署 Visual Studio 的更多信息，请参见 KB 文章 327792“HOW TO: Deploy Visual Studio .NET 2005 by Using Systems Management Server”（如何：使用 Systems Management Server 部署 Visual Studio .NET 2005）（位于 http://go.microsoft.com/fwlink/?LinkId=51517）。
  • Active Directory 部署
    此方法使网络管理员可以借助 Active Directory 来部署 Visual Studio。网络管理员首先将所需的包解压缩到不同的文件夹中，然后按指定的顺序来部署所需的 Visual Studio 组件。接着，将 .msi 文件添加到为 Visual Studio 部署创建的 Active Directory 组策略中。所有后续组件都应该按照它们的部署顺序添加到该组策略中。启用此组策略后，属于该组策略的所有客户端都将在启动时自动安装这些组件。如果发生错误，安装程序将因失败而自行退出。

说明：

  1. 本文档所提到的软件（包括但不限于 Microsoft Visual Studio 2005、Active Directory 和 Visual SourceSafe）均受许可条款和条件的制约。这些说明假定软件的相应被许可方已查看并接受此类许可条款和条件。这些说明不免除此类许可协议中的任何条款和条件。
  2. 不能在装有 Intel Itanium 处理器的计算机上安装 Visual Studio 2005。将 Visual Studio 2005 MSI 部署到装有 Itanium 处理器的计算机的尝试将会失败。
  3. Visual Studio 2005 安装中不包括 Visual SourceSafe。但是，您可以将 Visual SourceSafe 的内容复制到服务器上的一个单独的文件夹中，以便于通过网络来单独安装这些产品。
  4. 对于 Windows XP、Windows 2000 和 Windows 2003，必须在计算机上安装 Windows Installer 3.1。要下载 Windows Installer 3.1，请转到 http://go.microsoft.com/fwlink/?LinkId=51558。

2. 通过管理员安装模式部署 Visual Studio 2005

2.1 运行管理员安装模式

步骤 1：检查系统必备组件

在进行管理员安装过程这一阶段之前，必须在目标客户端上安装 Visual Studio 的系统必备组件。要安装任何系统必备组件或可选组件，目标计算机上都必须要有 Windows Installer 3.1。下面列出了 Visual Studio 2005 必需的组件。如果不符合系统必备要求，则 Visual Studio 无人参与安装将失败。

  • 在 Windows 2003 上，要求安装 Service Pack 1。
  • 在 Windows 2000 上，要求安装 Service Pack 4。
  • 在 Windows XP 上，要求安装 Service Pack 2。
  • 所有平台都要求安装 Microsoft Internet Explorer 6 Service Pack 1。

步骤 2：创建 .ini 文件

  1. 插入 Visual Studio 2005 CD 或 DVD 并忽略自动运行消息。
  2. 从“开始”菜单中选择“运行”。
  3. 键入以下命令：

    n:\setup\Setup.exe /createunattend <.ini 文件的路径>

    例如：

    D:\setup\setup.exe /createunattend c:\vs2005_deployment.ini

  4. 按照安装程序“起始页”上的说明进行操作，然后单击“继续”。
  5. 在“选项页”上，选择要部署的功能，然后单击“完成”。

步骤 3：创建网络映像

  1. 在服务器上创建一个文件夹。例如 <驱动器>:\VS2005。
  2. 在顶层文件夹中，分别创建两个名为 VS 和 MSDN 的子文件夹。例如：<驱动器>:\VS2005\VS 和 <驱动器>:\VS2005\MSDN
  3. 将标有 Visual Studio 2005 的所有 CD 的内容复制到名为 VS 的子文件夹中。如果提示您覆盖现有文件，请照做。
  4. 将所有带有 MSDN Library for Visual Studio 2005 标签的 CD 的内容复制到名为 MSDN 的子文件夹中。如果提示您覆盖现有文件，请照做。
  5. 使用文本编辑器（如“记事本”）打开 VS 子文件夹中的 setup.ini。
  6. 在 [Documentation] 节中，将以“DIR=”开头的行更改为“DIR=..\MSDN”。例如：
    [Documentation]
    DIR=..\MSDN
  7. 保存更改并关闭文件。
    注意：完成此步骤可防止安装过程中要求更换磁盘，并可将 MSDN Library CD 的正确路径通知安装程序。
  8. 在 VS 子文件夹中，打开 Setup 文件夹。
  9. 使用文本编辑器（如“记事本”）打开 setup.sdb，并在文件末尾添加下面几行内容：
    [Product Key]
    XXXXXXXXXXXXXXXXXXXXXXXXX
    注意： XXXXXXXXXXXXXXXXXXXXXXXXX 是 25 个字符的产品密钥，在 CD 包装上可以找到该产品密钥。输入产品密钥时不要带短划线。
  10. 保存更改并关闭文件。
    注意：完成此步骤可启用为用户预先填写产品密钥。
  11. 在网络上共享 VS2005 文件夹并设置适当的安全设置。网络上的 Visual Studio 2005 安装程序的路径的形式如下：\\<服务器名>\VS2005\VS\setup.exe。
    注意：
    • 在安装时，如果任何路径和文件名的组合超过 260 个字符，安装将会失败。Visual Studio 中路径的最大长度为 221 个字符，因此应将文件复制到一个少于 70 个字符的路径中。如果为网络映像创建网络共享，根安装位置的 UNC 路径应该不超过 39 个字符。
    • 如果此路径中的文件夹名称包括嵌入的空格，例如“\\<服务器名>\VS 2005\MSDN\”或“\\<服务器名>\VS2005\Visual Studio\”，则安装可能会失败。

步骤 4：在客户端上用 .ini 文件运行安装程序

  1. 确认网络上有 Visual Studio 2005。
  2. 从“开始”菜单中选择“运行”。
  3. 键入以下命令：

    \\<计算机>\<共享位置>\...\setup\Setup.exe /unattendfile <.ini 文件的路径>

    例如：

    \\server\VisualStudio\setup\setup.exe /unattendfile \\server\share\vs2005_deployment.ini

步骤 5：运行 MSDN Library 安装程序（可选）

  1. 确认网络上有 MSDN Library。
  2. 从“开始”菜单中选择“运行”。
  3. 键入以下命令：
    非安静安装：

    msiexec /i <msdn.msi 的路径（位于安装源的根目录下）>

    无人参与安装：

    msiexec /qb /i <msdn.msi 的路径（位于安装源的根目录下）>

    例如：

    msiexec.exe /qb /i \\products\VisualStudio\MSDN

注意：有关 MSDN 安装选项的更多详细信息，请参考顶层 MSDN 文件夹中的自述文件。

2.3 安装维护

可以在已完成安装的计算机上再次运行安装程序，以使用安装维护功能。用户或管理员应从“控制面板”的“添加/删除程序”中运行安装程序。若要使用安装程序的维护模式，用户需要使用本地计算机的管理权限进行登录。

3.2 使用 Active Directory 部署组件

本节描述使用 Active Directory 通过网络部署特定组件的 Windows Installer 安装程序包的具体过程。要部署需要使用管理员特权来解压缩文件的组件，必须从 .exe 文件解压缩 Windows Installer 文件。例如，要部署 .NET Framework Redistributable Package，必须从 .exe 文件解压缩要用于部署的 Netfx.msi 文件。

可以在 Active Directory 客户端计算机上安装 Windows Installer 安装程序包之前，客户端计算机上必须已安装 Windows Installer 安装服务。本节描述的过程假定在部署任意组件之前，已在所有客户端计算机上安装了 Windows Installer 3.1。

对于 .NET Framework 部署，有一些安装之前必须满足的最低配置要求。有关特定的软硬件要求及推荐配置，请参见位于 http://go.microsoft.com/fwlink/?LinkId=52324 上的“Deploying & Configuring Applications”（部署和配置应用程序）。

步骤 1：创建管理员安装点

  1. 将组件的 .exe 文件或 .msi 文件（具体位置请见表 2）下载到本地计算机上的 C:\ 驱动器的根目录下。
  2. 从“开始”菜单中选择“运行”。
  3. 将目录更改为 C:\ 驱动器的根目录。
  4. 在命令提示符处键入以下命令，以创建要将 .exe 文件复制到其中的目录：
    mkdir [目录名]
  5. 键入相应的组件命令（见表 2），以便在该目录中创建安装点。
  6. 关闭命令提示符窗口。
  7. 打开 Windows 资源管理器然后定位到 c:\[目录名]，以确认文件已解压缩。
  8. 将该文件夹及其所有内容移到要用于部署的网络共享。

步骤 2：向 Active Directory 组策略添加安装程序包

  1. 从“开始”菜单中选择“程序”，然后选择“管理工具”。
  2. 选择“组件服务”，然后展开“Active Directory 用户和计算机”。显示“Active Directory 用户和计算机”树。
  3. 右击“域”节点，然后选择“属性”。
  4. 在“属性”对话框中选择“组策略”选项卡，然后单击“编辑”。
  5. 如果要设置应用于计算机的策略，而不管登录到计算机的是哪些用户，请展开“计算机配置\软件设置”。
    注意：确保映射到 Active Directory 服务器上的共享位置；否则将无法创建用于安装的包。
  6. 右击“软件安装”，选择“新建”，然后选择“程序包”。
  7. 在“打开”对话框中，浏览到已将部署文件夹复制到的位置，然后选择 .msi 文件。
  8. 在“部署软件”对话框中选择“已指派”，然后单击“确定”。
  9. 选择“自动安装”以在域中的每台计算机上自动安装软件。
  10. 单击“确定”，然后退出“Active Directory 用户和计算机”控制台。

步骤 3：通过组策略设置升高的特权

由于多数程序包只允许由计算机的本地管理员进行安装，因此，您应使用升高的特权在组策略中向每台计算机播发程序包。网络管理员可以为一个用户、一台计算机或一组用户创建策略。有关创建特殊策略配置文件的更多信息，请参见“系统策略编辑器帮助”是；有关配置策略的更多信息，请参见“组策略管理单元帮助”。

  1. 从“开始”菜单中选择“程序”，然后选择“管理工具”。
  2. 选择“组件服务”，然后展开“Active Directory 用户和计算机”。显示“Active Directory 用户和计算机”树。
  3. 右击“域”节点，然后选择“属性”。
  4. 选择“组策略”选项卡
  5. 在“组策略对象链接”框中选择组策略对象，然后单击“编辑”。
  6. 打开“本地计算机策略\管理模板\Windows 组件\Windows Installer”文件夹。
  7. 在细节窗格中双击“永远以高特权进行安装”策略。
  8. 在“组策略属性”对话框中启用该策略，选中复选框以打开该设置，然后单击“确定”。
  9. 打开“用户配置\管理模板\Windows 组件\Windows Installer”文件夹，并重复步骤 8 和 9。

注意：可以使用系统策略编辑器和 Windows Installer 策略来设置“永远以高特权进行安装”策略。必须为计算机和每个用户设置策略。如果选择不使用组策略编辑器或系统策略编辑器，可以通过更改 Windows 注册表项的值，在每台计算机上指定相同的设置。

步骤 4：确认可以将包分配给计算机

  1. 在“[组件名称] - 英语属性”对话框中，选择“部署”选项卡。
  2. 在“部署类型”下选择“已指派”。
  3. 在“部署选项”下，选择有关何时以及如何部署组件的正确选项。
  4. 浏览其他可用的选项卡，并根据需要进行选择。有关详细信息，请参见对话框中的“组策略帮助”。

步骤 5：部署其他必需的组件

要部署其他 Visual Studio 组件，只需重复步骤 1，将 .msi 文件添加到指定的 Active Directory 组策略中。

3.3 为 Visual Studio 安装创建转换

3.4 使用组策略对象创建部署

必须为 Active Directory 部署创建 Visual Studio 2005 及所有相关文件的管理安装点。您必须具有服务器上的管理安装点的写入权限，以及使用 Active Directory 部署 Visual Studio 的相应权限。Visual Studio 安装程序接受多个不同的命令行选项。可以使用 /a 命令行选项创建管理安装点。下表列出了用于安装的所有命令行选项：

表 3. Visual Studio 安装程序命令行选项列表。
命令行选项 说明
[start] 仅对 Msiexec 未直接包括在路径中的 Windows 98 系统是必需的。
Msiexec Windows Installer 的可执行文件名称。
/p 允许 Windows Installer 对现有安装应用更新。
[MSP 更新文件的路径\名称] 用于更新的 MSP 文件的路径和文件名。
/a 允许 Windows Installer 在网络共享上执行产品的管理安装。
[MSI 文件的路径\名称] 原始管理映像的 Windows Installer 包的路径和文件名。
/qb 将用户界面设置为基本级别（简单的进度和错误处理）。

5. 已知的安装问题

5.1. 无法创建数据文件

如果您使用现有的文件在 createunattend 模式下运行安装，将显示下面的错误信息：“无法创建数据文件 <文件名 >。安装程序无法继续。”

您可以删除现有文件或提供唯一的文件名以更正此错误。

5.2. 用户特定数据的可见性

当创建无人参与的安装文件时，文件中可能会出现某些用户特定的数据。具体说来，创建文件的用户的名称及其单位名称会显示为两行文字：

  • gfn_pid core user name=您的用户名
  • gfn_pid core organization=您的公司

在使用 .ini 文件之前，您可以更改这些变量的值，但不要完全删除这些行。

6. 疑难解答

6.1. Visual Studio 日志文件位置

在 Visual Studio 2005 安装过程中生成下列日志文件：

  • dd_vserror80.txt
  • dd_vsinstall80.txt
  • VSMsiLog****.txt（其中 * 是随机生成的后缀）

在 Visual Studio 安装过程中，这些日志文件位于 %temp% 目录中。例如：

C:\Documents and Settings\[用户名]\Local Settings\Temp

Visual Studio 安装完毕后，这些日志文件位于 Visual Studio 安装路径下的 Logs 目录中。例如：

C:\Program Files\Microsoft Visual Studio 8\[产品名称]\Logs

如果 Visual Studio 安装和卸载失败，则这些日志文件仍在 %temp% 目录中。

注意：Microsoft SQL Server Express、Visual Studio .NET Framework 和 Visual Studio J# Redistributable Package 等其他 Visual Studio 组件也将生成日志文件。这些日志文件在 %temp% 目录或 [驱动器]:\Program Files\Microsoft SQL Server\90\Setup Bootstrap\LOG 目录下。
