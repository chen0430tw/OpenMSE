Microsoft .NET Framework SDK 2.0 版自述文件

感谢您使用 .NET Framework SDK 2.0 版。 我们希望使 .NET Framework SDK 2.0 版成为有史以来最优秀的软件开发人员工具包。为此，我们需要您的帮助。 我们提供了可以联机使用的反馈链接， 并鼓励您提出宝贵意见和要求。

本 SDK 包括一些演示最新 .NET Framework 技术的新示例。 这些示例位于 SDK 文档的快速入门部分或位于 LateBreaking SDK 文件夹中。 您也可以从下载中心的单个 Zip 文件中联机获取这些示例。

.NET Framework SDK 包括文档、示例代码、工具以及用于开发面向 .NET Compact Framework 的代码的引用程序集。 若要安装 .NET Compact Framework 引用程序集和 MSBuild 文件，请安装位于 SDK 的 CompactFramework 子目录中的 NETCFSetUpV2.msi。 有关受支持方案的更多信息，请参见 SDK 文档。

说明

1. 启动安装程序时，默认的安装位置是您的系统驱动器（启动系统的驱动器）。不过，您可以在任何驱动器上安装应用程序。不论应用程序安装在什么位置，安装进程都会在系统驱动器上安装一些文件。 因此，您应当确保系统驱动器和安装驱动器（如果安装驱动器不是系统驱动器）上有足够的可用空间。

2. 如果使用的是 Windows 2000，您需要解压缩实用工具，才能访问文档中存储的示例和下载中心上单个示例 Zip 文件中存储的示例。

3. .NET Framework SDK 支持所有 64 位平台上的 Windows-on-Windows (WOW)。

2. 已知问题

     2.1 配置和安装

          2.1.1 SQL Server Express 不适用于 Itanium 版的 SDK

               Itanium 版 SDK 中随带的一些 SQL 快速入门示例要求使用示例数据库并配置为与 SQL Server Express 一起使用。

               解决此问题的方法

               安装 64 位版本的 Microsoft SQL Server 2005，并从命令行运行

ConfigSamples.exe –sql_instance:<Microsoft SQL Server 2005 实例名>

以将快速入门示例设置为使用 Microsoft SQL Server 2005。

          2.1.2 修复 SDK 时无法安装以前未选中的组件

               安装 SDK 时，您可以选择安装不同的组件。 重新运行 SDK 安装程序并选择“修复”时，无法安装以前未选中的组件。

               解决此问题的方法

               卸载然后重新安装 SDK。

          2.1.3 64 位 SDK 在安装期间无法检测到硬盘已满的情况

                如果尝试安装 64 位 SDK 时您指定的硬盘已满，安装程序将停止响应，并显示“安装程序正在进行安装配置”而不是显示指出磁盘已满的错误信息。

               解决此问题的方法

               取消 SDK 安装，在硬盘上留出所需的空间量，然后重新安装。

          2.1.4 64 位 SDK 中的 SignTool.exe 在执行时显示 CAPICOM 版本错误

                如果您在 64 位计算机上安装了 SDK 而没有安装 Visual Studio 2005，则在使用 SignTool.exe 进行签名时将引发以下错误：

               SignTool 错误： Signtool 要求 CAPICOM 2.1.0.1 版或更高版本。 请将最新版本的 CAPICOM.dll 复制到包含 SignTool.exe 的目录中。如果 CAPICOM.dll 存在，则可能是您没有安装 CAPICOM 的正确权限。

               这是因为 CAPICOM.dll 未正确注册。

               解决此问题的方法

               将 CAPICOM.dll 从 Program Files\Common\Microsoft Shared\CAPICOM 复制到 SignTool.exe 所在的目录。

          2.1.5 如果在安装 Visual Studio 2005 或 SDK 之后安装 Internet Information Server，ConfigSample.exe 将失败

                如果您按下面的顺序安装 SDK 示例：
  1. 安装 Visual Studio 2005 或 SDK
  2. 安装 Internet Information Server
  3. 执行 ConfigSample.exe 以设置示例进行查看
ConfigSample.exe 将失败。

               解决此问题的方法

               
  1. 从 SDK 命令提示符下运行

    aspnet_regiis.exe -u

  2. 重新运行 ConfigSamples.exe

     2.2 示例

          2.2.1 某些示例需要 Platform SDK 标头

               以下示例需要 Platform SDK 标头：

CLR Versioning
GCDemo
Callback
ClassMethods
PInvoke

               解决此问题的方法

               必须使用 Windows 头文件生成这些示例。 Visual C++ 中提供了 Windows 头文件（通过使用 Visual Studio 2005 命令提示符并设置正确的包含路径），也可以通过使用 Platform SDK 并设置包含路径来获得 Windows 头文件。 这是因为 .NET Framework 并不附带可以在 Visual C++ 和 Platform SDK 中找到的所有非托管标头。 您可以从下载中心下载 Platform SDK，它包括所有 Windows 头文件。

          2.2.2 某些示例不能从命令窗口运行

               以下示例不能在命令环境中运行，而必须在 Visual Studio 2005 中运行：

应用程序示例
SecureString

技术示例
CLR Version Detection

               解决此问题的方法

               1. 打开 Windows 资源管理器并定位到示例目录中的 .exe 文件（对于 SecureString 示例为 SecureStringConsoleDemo.exe，对于 CLR Version Detection 示例为 CLRVer.exe）。
2. 双击该 .exe 文件。

          2.2.3 SQL CE ResultSet 示例需要 SQL CE

               若要使用 SQL CE ResultSet 示例（一个具有 .NET Compact Framework 示例的技术示例），您必须安装 SQL CE（随 Visual Studio 2005 提供）。

               解决此问题的方法

               安装 Visual 2005，在安装过程中，安装程序会在安装“智能设备项目”时默认安装 SQL CE。

          2.2.4 重写 CPU 配置以使用 MSBuild 生成 C++ 示例

               某些 C++ 示例具有的默认 CPU 配置与您的编译器当前支持的配置不同，因此导致错误。

               解决此问题的方法

                若要使用 64 位 .NET Framework 2.0 SDK 生成 C++ 示例，请在命令行中输入以下命令：

对于基于 x64 的系统：
Msbuild mySolution.sln /p:Platform=x64

对于基于 Itanium 的系统：
Msbuild mySolution.sln /p:Platform=Itanium

若要进行交叉编译以面向在其中进行开发的不同平台，您需要安装 Visual Studio 2005。

          2.2.5 某些具有项目到项目特性的 C++ 示例不能用 Msbuild 进行编译

               快速入门示例
“如何”部分下的远程处理示例的所有 C++ 实现

技术示例
通过配置进行的远程处理

               解决此问题的方法

                使用 VCbuild 而不是 Msbuild 来从解决方案文件生成示例。

例如：
VCbuild mySolution.sln

          2.2.9 快速入门中的“在 VWD 中使用数据库”示例在对列排序时显示错误

               快速入门的“执行数据访问”部分中的“在 VWD 中使用数据库”示例在您尝试通过单击“ID”或“名称”列标题对表进行排序时，显示“无法找到列 ID”错误。

               解决此问题的方法

               若要修复此错误，请按如下方式编辑 <sdk 安装路径>\QuickStart\aspnet\samples\data 中的 SQLExpress_cs.aspx 和 SQLExpress_vb.aspx：

                将 SQLExpress_cs.aspx 和 SQLExpress_vb.aspx 中的以下内容
<Columns>
     <asp:BoundField DataField="ContactID" HeaderText="ID" ReadOnly="True" SortExpression="ID" />
     <asp:BoundField DataField="ContactName" HeaderText="Name" SortExpression="Name" />
</Columns>
替换为
<Columns>
     <asp:BoundField DataField="ContactID" HeaderText="ID" ReadOnly="True" SortExpression="ContactID" />
     <asp:BoundField DataField="ContactName" HeaderText="Name" SortExpression="ContactName" />
</Columns>
