# 工具箱与布局设计器

统一 GUI 已按左侧工具箱、中央文档/设计画布、右上项目树、右下属性的布局组织。中央文档底部可切换“设计 / HTML”或“设计 / 布局 JSON”；生成输出面板按需展开。

## 工具箱来源

`config/toolbox.json` 包含两个分类：

- HTML：从本机 MSE 配置模板的 `DefaultToolbox\Tab 0\Element …` 提取了 17 个原始条目和 HTML 片段，包括按钮、提交/重置、文本域、复选框、单选框、表格、布局面板、图像和列表。可用 `scripts/export-toolbox.py` 重新生成。
- Windows 窗体：22 个与 VS2005 标准工具箱对应的 Windows Forms 控件。设计时使用新 GUI 的 .NET Framework 4 控件，导出的 C#/VB 源码使用 .NET 2.0 类型；这不是加载 VS2005 原设计器包。

原有 ActiveX、Office 和第三方设计器没有加入这个可用目录，仍通过旧引擎兼容窗口使用。

## 操作

1. 在工具箱底部点击“新建 HTML”或“新建窗体”，也可从共用新建对话框选择模板。
2. 双击工具箱控件添加，或拖放到画布。工具箱会随活动文档切换分类；跨类型控件不能插入。
3. 点击控件选择；拖动移动，拖动右下角调整大小。位置和大小按 10 像素网格对齐。
4. 在右侧修改 Name、Text、X/Y、Width/Height 和颜色属性。按 Delete 删除选中的元素；HTML 容器的删除包含其内部内容。
5. 保存 HTML 为 `.html` / `.htm`。窗体布局保存为 `.omform`，通过“项目 → 导出窗体 C# / VB 源码”生成独立可编译的窗体程序。

可打开 `samples/designer-demo.html` 或 `samples/WindowsForm.omform` 查看示例。

## 文件语义

HTML 的设计操作只替换所选元素的源码片段，或在 body 结束前插入新片段；不通过完整 DOM 重新序列化文件。仅切换视图不会修改源码。源码改变后，设计操作会先重新加载并拒绝使用过期位置，避免覆盖较新的编辑。

HTML 画布是静态布局示意，不执行脚本，也不加载网页图片或网络资源；它不是完整浏览器或 MSE HTML 设计器。未知标签仍保留在源码中，但可能不显示。CSS、嵌套容器、字体、响应式布局和表单选项未完整呈现，布局修改使用绝对定位。包含子标签的元素不能通过 Text 属性覆盖其内部结构，需在源码视图修改。

Windows 窗体布局 v1 使用 JSON 保存单层控件集合，校验名称、类型和尺寸。此版不支持容器嵌套、事件代码、数据绑定、资源、已有 Designer.cs 的反向导入或 `.resx`。窗体源码导出不覆盖用户事件文件，也不会自动将导出文件加入原工程。新界面并未托管两套旧引擎的工具箱服务或旧设计器窗口。

## 验证

`tests/gui/DesignerSmoke.cs` 随 GUI 验证入口执行，检查 HTML 插入/属性写回/删除/保存重开、未知源码保留、视图切换、过期源码和跨类型保护，以及全部 22 个窗体控件导出后分别通过 .NET 2.0 C#、VB 编译。测试还验证属性面板与当前选择同步。

运行 `bin\OpenMSE.Shell.exe --smoke-test <新的独立测试目录>`。最近一次测试位置记录在 `logs/designer-smoke-path.txt`，报告为该目录内的 `results.txt`，真实窗口截图为 `gui.png`。测试目录须独立于用户项目。
