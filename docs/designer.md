# 工具箱与布局设计器

统一 GUI 已按左侧工具箱、中央文档/设计画布、右上项目树、右下属性的布局组织。中央文档底部可切换“设计 / HTML”或“设计 / 布局 JSON”；生成输出面板按需展开。

## 工具箱来源

`config/toolbox.json` 包含两个分类：

- HTML：从本机 MSE 配置模板的 `DefaultToolbox\Tab 0\Element …` 提取了 17 个原始条目和 HTML 片段，包括按钮、提交/重置、文本域、复选框、单选框、表格、布局面板、图像和列表。可用 `scripts/export-toolbox.py` 重新生成。
- Windows 窗体：22 个与 VS2005 标准工具箱对应的 Windows Forms 控件。设计时使用新 GUI 的 .NET Framework 4 控件，导出的 C#/VB 源码使用 .NET 2.0 类型；这不是加载 VS2005 原设计器包。

原有 ActiveX、Office 和第三方设计器没有加入这个可用目录，仍通过旧引擎兼容窗口使用。

## 操作

1. 在工具箱底部点击“新建 HTML”或“新建窗体”，也可从共用新建对话框选择模板。
2. 双击工具箱控件添加，或拖放到画布。工具箱会随活动文档切换分类；跨类型控件不能插入。
3. 点击控件选择；拖动移动，拖动右下角调整大小。位置和大小按 10 像素网格对齐。
4. 在右侧修改 Name、Text、X/Y、Width/Height 和颜色属性。按 Delete 删除选中的元素；HTML 容器的删除包含其内部内容。
5. 保存 HTML 为 `.html` / `.htm`。窗体布局保存为 `.omform`，通过“项目 → 导出窗体 C# / VB 源码”生成独立可编译的窗体程序。

可打开 `samples/designer-demo.html` 或 `samples/WindowsForm.omform` 查看示例。

## 窗体代码

和 VB/VBA 一样，一个窗体只有一个代码窗口（`Form1.vb` 或 `Form1.cs`），每个事件是其中的一个过程。

- **双击**控件打开它的默认事件（Button 为 Click、TextBox 为 TextChanged、窗体为 Load 等）。第一次会创建过程，之后只跳转。
- **代码窗口顶部的两个下拉框**：左边选对象（窗体或控件），右边列出该对象的全部事件，已有过程的事件显示为粗体。选中一个事件就创建并跳到对应过程。移动光标时，两个下拉框会显示当前所在的过程。事件列表来自 .NET 2.0 的 Windows Forms，和生成的程序一致。
- **文件**：`Form1.omform` 的 `Events` 记录绑定；`Form1.vb/.cs` 是你的代码，只会追加过程；`Form1.Designer.vb/.cs` 是生成的布局代码，每次保存布局时重写，没有 OpenMSE 生成标记的同名文件不会被覆盖。
- **未保存的窗体**：不需要先保存，双击后会询问语言，并打开一个未命名的代码窗口。窗体第一次保存时，代码一并保存到它旁边，类名按最终文件名改正，同时生成 Designer 文件并加入项目；如果同名代码文件已存在，则不覆盖，代码保留在未命名标签中。窗体未保存时保存代码，会改为保存窗体。
- **语言**：已保存的窗体依次取已有的代码文件、所在的项目；未保存或都没有时会询问。类名来自文件名，中文等字母会保留。
- **项目**：布局在已打开项目的目录内时，代码文件和所需引用会写入项目文件。程序入口不会自动修改，需要自己写 `Application.Run(New Form1())`。
- **HTML**：双击加上 `onclick`（文本和列表类为 `onchange`），并在最后一个内联脚本中补上函数；没有脚本时在 `</body>` 前新建脚本块。一次撤销即可全部撤回。

“导出窗体源码”生成的独立程序不包含事件代码。

## 文件语义

设计模型、源码补丁和校验都在内核 `OpenMSE.Core` 中，详见[文档与设计内核](kernel/core.md)。每个设计操作都是一笔带版本的事务：一次源码修改、一步撤销，可在源码视图中立即看到。

HTML 的设计操作只替换所选元素的源码片段，或在 body 结束前插入新片段；不通过完整 DOM 重新序列化文件。仅切换视图不会修改源码。源码改变后，过期的设计操作会被内核以版本冲突拒绝，设计视图随即重新加载，避免覆盖较新的编辑。

HTML 画布是静态布局示意，不执行脚本，也不加载网页图片或网络资源；它不是完整浏览器或 MSE HTML 设计器。未知标签仍保留在源码中，但可能不显示。CSS、嵌套容器、字体、响应式布局和表单选项未完整呈现，布局修改使用绝对定位。包含子标签的元素不能通过 Text 属性覆盖其内部结构，需在源码视图修改。

Windows 窗体布局 v1 使用 JSON 保存单层控件集合，校验名称、类型和尺寸。修改时只替换对应的 JSON 值，保留原有缩进和未知字段。此版不支持容器嵌套、数据绑定、资源、已有 Designer.cs 的反向导入或 `.resx`。窗体源码导出不覆盖用户事件文件，也不会自动将导出文件加入原工程。新界面并未托管两套旧引擎的工具箱服务或旧设计器窗口。

## 验证

`tests/gui/DesignerSmoke.cs` 随 GUI 验证入口执行，检查 HTML 与窗体各自的“拖放 → 属性修改 → 源码同步 → 撤销/重做 → 保存 → 关闭重开”闭环，以及未知源码保留、视图切换、过期版本、跨类型和无效属性保护。它还检查手写格式布局只改动一个值，以及全部 22 个窗体控件导出后分别通过 .NET 2.0 C#、VB 编译。测试同时验证属性面板与当前选择同步。

运行 `bin\OpenMSE.Shell.exe --smoke-test <新的独立测试目录>`。最近一次测试位置记录在 `logs/designer-smoke-path.txt`，报告为该目录内的 `results.txt`，真实窗口截图为 `gui.png`。测试目录须独立于用户项目。
